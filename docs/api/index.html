Resttek API

Versión 1.0.0 · OpenAPI 3.1.0 · Servidor: http://localhost:3000

API REST de Resttek, plataforma de gestión de restaurantes.

Autenticación

Los endpoints protegidos exigen la cabecera Authorization: Bearer <token>. El token (JWT con id, role y restaurantId) se obtiene con POST /api/v1/auth/login o POST /api/v1/auth/register.

Roles

admin, manager (gerente), camarero, cocinero y cliente. Cada operación indica en su descripción qué roles admite. Si solo dice autenticado, basta con un token válido de cualquier rol.

Errores

Conviven dos formatos:

  • ErrorResponse ({ error, message }): errores de dominio gestionados por el errorHandler. error es el nombre de la clase de error (p. ej. RestaurantNotFoundError).
  • SimpleError ({ error }): errores de autenticación (401), autorización (403) y todos los de /api/v1/orders.

Datos de prueba

Tras npm run seed, la contraseña de cada usuario es su propio email: admin@resttek.com, gerente1@resttek.com, cocinero1@resttek.com, camarero1@resttek.com, cliente1@resttek.com.

Pedidos

Pedidos y estado de cada unidad pedida

POST /api/v1/orders Bearer JWT

Crear un pedido

Roles: autenticado. El clientId se toma del token. Cada ítem con quantity: N se expande en N ítems con quantity: 1 y estado pendiente, para seguir el estado de cada unidad por separado.

Cualquier error (incluido un restaurantId vacío o inexistente) se devuelve como 400 SimpleError.

Cuerpo de la petición obligatorio

OrderInput

CampoTipoDetalles

tableId string | null default: null
items obligatorio object[]
CampoTipoDetalles
dishId obligatorio string (uuid)
quantity obligatorio integer Se expande en quantity ítems
minimum: 1
notes string | null

Respuestas

CódigoDescripciónCuerpo

500 Error no controlado ({ "error": "Internal Server Error" }) SimpleError
